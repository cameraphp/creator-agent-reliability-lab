# Audit report — synthetic lab findings (eval-v1)

Derived from actual local runs of `npm run evaluate:baseline` (exit 3) and `npm run evaluate:hardened`
(exit 0) over the same 32 versioned scenarios (`evaluations/v1/dataset.json`). The baseline is a
**deliberately defective CLI-only model** of a plausible pre-remediation design. These are lab findings,
not findings about any client or real product, and the impacts below are illustrative.

Evidence locations: `.artifacts/eval/{baseline,hardened}-eval-v1.{json,md}`, `.artifacts/eval/comparison-eval-v1.md`
(samples copied to `docs/evidence/`). Hardened per-job trace events are stored in each scenario's `trace_evidence`.

---

## F01 — Wrong route and unsafe retry/fallback after provider uncertainty

|                        |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Observed (baseline)    | 7/10 F01 scenarios defective. `F01-02` (timeout after acceptance) and `F01-03` (late result): 3 billable ops instead of 2. `F01-01` (fast brief): routed to `quick-classify` (2k window < 4k task requirement), truncated output leniently accepted → `SCHEMA_INVALID` artifact saved. `F01-05`: backup without idempotency times out after acceptance; baseline marks the job ready via a second paid call, then the user's retry creates a new job (5 billable ops, `DUPLICATE_JOB`, `OUTCOME_MISMATCH`). `F01-09`: stale attempt's late result rewrote the terminal artifact (`TERMINAL_OVERWRITTEN`). Route agreement 4/8. |
| Reproduced local cause | `routeBaseline` ignores context window/output mode and picks the cheapest profile for "fast"; any non-response (including an ambiguous timeout) triggers an immediate fallback with a new random operation id; `lenientParse` salvages fragments; no fencing.                                                                                                                                                                                                                                                                                                                                                                  |
| Illustrative impact    | Double synthetic charges per uncertain call; invalid drafts presented as ready; an unknown upstream charge hidden behind a "done" state.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Severity rationale     | High: silent spend + silent wrong output, and the failure is invisible without a ledger.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Fix                    | Compatibility router with exclusion reasons (`route.decision` trace); durable intent → receipt; reconcile via status lookup or idempotent replay; otherwise `RECONCILIATION_REQUIRED`; backup only after _known_ pre-acceptance failures; single shared attempt budget; fenced receipt commits; strict validation + one repair.                                                                                                                                                                                                                                                                                                |
| Hardened evidence      | 10/10 pass; route agreement 8/8; `F01-02` trace: `provider.ambiguous_timeout → reconciliation.status_lookup → provider.receipt_committed → draft.saved`; `F01-05` ends `RECONCILIATION_REQUIRED` with 2 billable ops and the user retry deduplicated to the same job.                                                                                                                                                                                                                                                                                                                                                          |
| Linked regressions     | Sentinel `T-S F01` (blind-fallback regression must raise `EXCESS_BILLABLE_OPERATIONS`); `T-U2`, `T-U4`, `T-U5`, `T-U6`, `T-U7`, `T-U8`, `T-C5`; `T-I1` (provider idempotency contract).                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Residual risk          | Reconciliation trusts the simulated provider's status API as authoritative after the deadline. Real providers' idempotency windows, status semantics and billing must be validated per provider. No remote cancellation exists. The idempotent-replay branch without status lookup has no fixture profile (covered only at provider-contract level).                                                                                                                                                                                                                                                                           |

## F02 — Chat switch / obsolete context delivers a result to the wrong journey

|                        |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Observed (baseline)    | 6/6 F02 scenarios defective; 12 wrong-context drafts saved. `F02-01`: draft delivered to `dn-conv-2` (the chat open at completion), not `dn-conv-1`. `F02-02`: desk-notes draft delivered into study-sparks' conversation (`CROSS_CREATOR_DELIVERY`). `F02-03`: study-sparks draft carries the desk-notes audience. `F02-04`/`F02-05`: superseded `tc-r1-battery` value saved after `tc-r2` (`STALE_OR_FOREIGN_FACT`). `F02-06`: unapproved "guaranteed to double productivity" note substituted when evidence was missing. Positive control `C03` also failed for the same root cause (provenance from a previous job). |
| Reproduced local cause | Context cache keyed by `product_id` only; destination taken from the client's _current_ active chat; unapproved notes used as fallback evidence.                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Illustrative impact    | A creator sees another creator's or another chat's draft; outdated or non-approved product claims reach a script.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Severity rationale     | High: confidentiality/ownership and factual-claim risk, not just quality.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Fix                    | Job-scoped context keyed by actor, original conversation, job and every pinned revision + policy; immutable `context_assembly` checkpoint is the source of truth (cache is convenience); destination = job's original conversation, enforced by composite FK; revision freshness checked before the paid call and before save (`STALE_REVISION`); missing approved evidence → `EVIDENCE_MISSING`.                                                                                                                                                                                                                        |
| Hardened evidence      | 6/6 pass; 0 wrong-context drafts; `F02-05` fails with `STALE_REVISION` after only 1 billable op (video).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Linked regressions     | Sentinel `T-S F02` (product-only cache regression must raise `WRONG_CONTEXT_DELIVERY`); `T-K4`, `T-K5`, `T-V3`, `T-V4`, `T-V5`; RLS suite `T-R1..T-R5`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Residual risk          | Revisions are an in-process simulated catalog; a real system needs revision pointers in the database and a policy for revisions published during review. Structured claim checks do not detect paraphrased unsupported claims.                                                                                                                                                                                                                                                                                                                                                                                           |

## F03 — Lost connection / crash / bad repair corrupt save and reopen

|                        |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Observed (baseline)    | 9/10 F03 scenarios defective. `F03-03`/`F03-04`: job `DRAFT_READY` with no artifact after a crash/DB failure between the two writes (`READY_WITHOUT_ARTIFACT`), then reopen regenerated it with 2 new paid invocations (`REGENERATED_ON_CLIENT_STEP`). `F03-02`: each resubmission created a new job (6 billable ops, 3 drafts). `F03-05`/`F03-09`/`F03-10`: restart reran every stage (3–4 billable ops). `F03-06`: repair appended → 12-line mixed script. `F03-07`: invalid 5-line draft saved instead of failing. `F03-08`: paused worker rewrote the terminal artifact. |
| Reproduced local cause | Terminal state written before the artifact in separate autocommit statements; no idempotency key; no checkpoints/receipts; restart requeues every `RUNNING` job; repair appended; no fencing or terminal guard.                                                                                                                                                                                                                                                                                                                                                              |
| Illustrative impact    | "Loading forever" or "ready but empty" screens, duplicate drafts, mixed scripts, repeated spend on reopen.                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Severity rationale     | High: user-visible corruption and spend on the most common mobile lifecycle events.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Fix                    | Atomic final transaction (candidate + stage checkpoint + draft + `DRAFT_READY`); idempotency key + server fingerprint (409 on changed input) + fixture-scoped semantic rule; receipts reused on restart; only expired leases reclaimed; repair = complete replacement validated from scratch, max one; DB trigger forbids terminal rewrites; reopen is read-only.                                                                                                                                                                                                            |
| Hardened evidence      | 10/10 pass; `F03-03` trace: `lease.reclaimed_expired → provider.receipt_reused → draft.saved`, 2 billable ops; real process crash tests `T-X` and smoke (exit 137 → recovery, still 2 accepted ops).                                                                                                                                                                                                                                                                                                                                                                         |
| Linked regressions     | Sentinel `T-S F03` (non-atomic final write must raise `READY_WITHOUT_ARTIFACT`); `T-K1`, `T-K2`, `T-K3`, `T-U1`, `T-U3`, `T-C3`, `T-C4`, `T-C5`, `T-J1..T-J3`, `T-X`.                                                                                                                                                                                                                                                                                                                                                                                                        |
| Residual risk          | Client delivery is simulated by API reads, not a real mobile app; push/notification delivery and offline caches are untested. The semantic dedupe rule only covers identical fixture selectors and pinned revisions.                                                                                                                                                                                                                                                                                                                                                         |
